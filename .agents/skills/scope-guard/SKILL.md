# スコープ評価

1. Issueと[Product Spec](../../../docs/product-spec.md)を読み、誰の課題を解くかと、承認された作業範囲・完了条件を確認する。
2. 現状維持と最小の変更案を比べる。利用者への価値、変更する挙動、守るべき要件、依存、技術リスク、実装と検証の負担を確認する。
3. 追加作業が必要なら、今回の完了条件に必要な理由と、新たに判断を要する項目を示す。独立できる変更は別Issueの候補にする。既存作業への影響があれば、延期や縮小の候補を示す。
4. 推奨する範囲、代替案、未確認事項を示し、採択や作業範囲の拡大は依頼者またはチームの判断を得る。

保守Issueの着手条件と大会時の分類の扱いは、[CONTRIBUTING](../../../CONTRIBUTING.md#statusとscope)を参照する。
