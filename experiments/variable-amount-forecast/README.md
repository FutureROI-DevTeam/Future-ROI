# 不規則な行動量から目標到達日を予測する

Future ROIの完了予測は、過去のDONEに記録された実量を累計へ入れ、未来のDONEには毎回の設定量を使う。ここでは「これまでの取り組み方が続くと、残り180分にいつ届くか」を調べた。記録済みの日の終わりから翌日以降を予測する。研究の起点は [Issue #352](https://github.com/FutureROI-DevTeam/Future-ROI/issues/352)、製品側の基準は [mainの計算](https://github.com/FutureROI-DevTeam/Future-ROI/blob/5f52416a49fbe908d0536b47277426682bb03e21/packages/prediction/src/completion-scenario.ts)。

初回の6方式と比較結果は以下に示す。[追加比較と追試](followup.md)では、似た人の到達日を参考にする方法と、短い履歴から本人の実行日数と実量を使う方法を、新しい合成日誌と公開活動記録で評価した。

その後、[大学生の学習日誌で80%到達日を検証した](study-p80.md)。予測日を1日遅らせたときに救える見積もりと、日付の遅れ・取り下げによる損失を実測した。

## 再現方法

リポジトリのルートから実行する。実験にはNode標準機能と既存の予測パッケージを使う。依存を取得できる環境で最初の2行を実行すれば、比較とテストはオフラインで動く。

```sh
npm ci --workspace=@futureroi/prediction --include=dev --ignore-scripts --no-audit --no-fund
npm run build --workspace=@futureroi/prediction
node --test experiments/variable-amount-forecast/research.test.mjs
node experiments/variable-amount-forecast/benchmark.mjs
```

最後のコマンドは比較条件ごとの人数、全モデルのRPS、P50・P80、モデル間差をJSONで返す。以下の結果はNode 22.15.1、TypeScript 5.9.3で再現した。

## 何を学習するか

| 出力のモデル名 | 実行する確率 | 実行した日の量 |
| --- | --- | --- |
| `m1Plan` | 現行M1。前日がDONEかSKIPPEDかに応じたBeta事後分布 | 設定30分 |
| `m1Mean` | 現行M1 | 本人の過去の正の実量の平均で固定 |
| `m1Empirical` | 現行M1 | 過去に記録した正の実量を、その出現割合で使う |
| `logisticPlan` | 本人の履歴で学習したロジスティック回帰 | 設定30分 |
| `logisticEmpirical` | 同じ回帰 | 本人の正の実量分布 |
| `logisticCalendarAmount` | 同じ回帰 | 平日と週末それぞれの正の実量分布 |

M1の3方式は実行頻度を共通にしている。`m1Mean` と `m1Empirical` の差は、平均量をそろえてもばらつきを扱う価値があるかを示す。独立な実行量を仮定し、必要なDONE回数の分布を求め、製品エンジンが返す回数別の到達CDFを重み付けする。固定量の分位点にはエンジンの閾値判定を使う。[予測コード](forecast.mjs)

回帰は、本人の記録のうち隣り合う既知の2日を教師例にする。説明変数は前日の実行有無と当日が週末かどうか。切片を含む3係数にL2罰則をかける（負の対数尤度の和＋係数二乗和、勾配への係数2）。未来の曜日は既知で、前日の実行は予測内で起きた状態を使う。回帰係数は点推定なので、M1との差には事後不確実性の扱いも含まれる。曜日別の量には本人の全実行日の分布を4回分加え、週末の記録が少ないときの振れを抑える。日ごとの実行確率と量を一緒に計算し、曜日と量の依存を保つ。係数は各人の過去だけから学び、比較時の正解から選んだ係数やハイパーパラメータは使わない。

## 比較条件と指標

- 設定30分、予測時点の残量180分、未来14日。各条件256人の合成日誌、1人1起点。過去7日と28日は別の集団。seedは `3522026`。開始曜日は巡回させ、個人ごとに実行しやすさを変えた。設定値・確率・乱数系列は [日誌生成コード](benchmark.mjs) にある。
- 一定量は毎回30分。変動量は5分か55分、設定より少ない条件は5分か25分で、それぞれ等確率。週末偏重では週末に実行しやすく、量も平日5分か15分、週末45分か75分となる。履歴は各日10%を独立に未記録にし、未来の正解は全日保持した。休みほど記録が抜ける状況はこの合成条件の対象外。
- 学習に渡すのは予測時点までの日付と量だけ。欠測をまたぐ遷移は数えない。起点が未記録、または現行M1の遷移材料が不足する人を全方式で除き、理由別人数を `notIssued` に残す。残りの人は到達の有無にかかわらず同じ未来で比較する。履歴が短い群の結果には、予測を発行できた人への選択がある。
- RPSは各日について「その日までに届く確率」と実際の到達有無の二乗差を取り、14日と発行人数で平均した値。小さい方が良い。P50・P80は各確率に初めて達する日で、14日内に届かない分位点は空になる。出力には日付が出せた人数・割合と、その人のうち実際にその日までに届いた割合を併記する。
- 各モデル間の差は同じ人・同じ未来でのRPS差。区間は独立した人を単位とする近似95%区間（対応差の平均 ± 1.96標準誤差、多重比較補正なし）。実到達件数と、常に「14日以内の到達確率0」とした参考RPSを出力し、到達がまれな条件を読み分ける。[集計コード](evaluate.mjs)

## 合成日誌での結果

各セルは平均RPS。発行人数の分母は各行256人。「到達」は発行できた人のうち14日以内に届いた人数。

| 行動 | 履歴 | 発行 / 到達 | M1・設定 | M1・平均 | M1・分布 | 回帰・設定 | 回帰・分布 | 回帰・曜日別量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 一定30分 | 7日 | 177 / 135 | .1283 | .1283 | .1283 | .1341 | .1341 | .1341 |
| 一定30分 | 28日 | 218 / 162 | .1258 | .1258 | .1258 | .1268 | .1268 | .1268 |
| 5分か55分 | 7日 | 187 / 136 | .1503 | .1827 | .1711 | .1643 | .1765 | .1773 |
| 5分か55分 | 28日 | 235 / 150 | .1530 | .1678 | .1545 | .1631 | .1597 | .1605 |
| 5分か25分 | 7日 | 180 / 21 | .1479 | .0255 | .0250 | .1664 | .0243 | .0244 |
| 5分か25分 | 28日 | 221 / 30 | .1624 | .0264 | .0257 | .1872 | .0257 | .0257 |
| 週末偏重 | 7日 | 191 / 140 | .1240 | .1583 | .1515 | .1291 | .1622 | .1558 |
| 週末偏重 | 28日 | 228 / 173 | .1188 | .1289 | .1269 | .1148 | .1245 | .1118 |

5分か25分の28日群では、実量分布が設定30分に対してRPSを0.1367下げた（対応差の95%区間 −0.1542〜−0.1193）。過去平均に替えるだけで .0264 になり、量の分布まで学ぶ上積みは小さい。期間中の到達は30/221人で、常に期間外を予測してもRPSは .0262 だった。実量分布で14日内のP80を発行できた人は0人なので、この群からP80の日付精度は評価できない。

5分か55分では、28日分の履歴で実量分布が過去平均より改善した（RPS差 −0.0133、95%区間 −0.0175〜−0.0091）。設定30分と比較すると差は +0.0015（−0.0076〜+0.0107）。真の平均に設定が合っているときは、量の分布を推定しても固定量を上回るとは限らない。

週末偏重の28日群では、曜日別の頻度と量を学ぶと設定30分の現行モデルより .0071 低かったが、差の95%区間は −0.0163〜+0.0021。7日群では逆に .0318 高かった（+0.0123〜+0.0513）。28日群でこの候補が14日内のP80を出したのは41/228人で、その日までに到達したのは30/41人。期間内で日付を出せるかと、その日付の当たり方の両方が採用判断に関わる。

## 手元の日誌での再実行

`--input` にローカルJSONを渡すと、同じ6方式と14日指標で比較する。1人につき事前に選んだ1起点を使う。下は架空の1人分。日付は履歴の初日、各配列は欠けた日も1要素とする連続した暦日。単位は分、実行は正の整数、明示した休みは0、未記録は `null`。未来は履歴末日の翌日から14要素必要となる。

```json
[{
  "startDate": "2026-01-05",
  "history": [5, 55, 0, null, 5, 0, 55],
  "future": [0, 5, null, 55, 0, 5, 55, 0, 0, 5, 55, 0, 5, 0]
}]
```

```sh
node experiments/variable-amount-forecast/benchmark.mjs --input local-windows.json
```

全員に設定30分・残り180分という同じ仮の目標を置く。後から訂正された記録を使う場合は、予測発行時点に見えていた版の履歴を用意する。未来に欠測がある場合は、既知の実量と矛盾しない初到達日を列挙し、各スコア・モデル間の対応差・到達割合の下限と上限を返す。期間内に到達しない場合も含む。到達日が複数考えられる人が残る場合は近似95%区間を出さない。複数起点を同じ人から渡すと、人数と独立性の解釈が変わる。

## 公開学習日誌で確認できたこと

Theobaldの大学生の自習日誌を2026-11-27に確認した。公開コードブックでは `nr` は参加者番号、`days` は1〜30の調査日、`study_time` は自己申告の自習時間（時間単位）。配布ファイルを集計すると245識別子・6,096行、正の時間3,975行、明示0時間256行、欠測1,865行だった。論文は解析対象231人、0時間で除いた229観測を報告する。ここでの件数は配布版全体の集計である。[論文](https://doi.org/10.1111/bjep.12725)・[OSFプロジェクト](https://osf.io/r9n4y/)・[コードブック](https://osf.io/v2b4s/)

配布表の確認に使った `data.RData` のSHA-256は `a1ca29477341999aaa58fea1c216e29acb9407d1c976f7d2aac8137873dc24af`。OSFの公開プロジェクトメタデータの `node_license` は空だった。30日の日誌では28日学習＋14日追跡を組めない。初回は合成日誌で比較し、その後の[80%到達日の研究](study-p80.md)で著者が公開した自習時間を用いて7日・14日履歴を評価した。[配布ファイル](https://osf.io/xuw8r/)・[プロジェクトメタデータ](https://api.osf.io/v2/nodes/r9n4y/)

採用を判断する次の比較では、実際の設定量と本人の実量のずれ、予測時点までに観測できた曜日、予測・追跡に足りる日数がそろう日誌が必要になる。合成条件で得た差から、実利用者の精度改善や標準Todayへの採用は決められない。
